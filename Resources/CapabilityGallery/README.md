# Capability Gallery

`CapabilityGallery.ui.html` and `CapabilityGallery.ui.css` are the authored surface for the native Capability Gallery host. They are consumed by `FCkCapabilityGalleryModel` through a per-player `FCkUiView`; they are not a browser reference and do not depend on CkDebuggerCommon.

The six retained tab keys are `layout`, `forms`, `data`, `collections`, `commands`, and `composition`. The gallery header keeps the bound title above its unchanged action controls, while each selected page supplies its own description. Tab headers wrap through the native tabs control at narrow widths. The outer shell, tab container, and page content have no broad minimum dimension, so narrow and scaled windows allocate the remaining viewport to the selected native scroll. The Data page keeps its own native vertical scrolling so its control rows lead to a 260px minimum splitter/table area; tables retain a horizontal scroll viewport.

The registered dialog is the document region root and carries no authored sizing. Its `gallery-root` content-slot child uses `flex-grow: 1; flex-shrink: 1;` so the gallery fills the dialog content mount without violating the region-root sizing rule.

The Layout page also contains a static inspectable layout and text lab. Its `layout-preview` outer overlay remains mounted at its authored 150px minimum height while `layout-toggle-preview` toggles the participating `layout-preview-content` child. In the empty state that child and the read-only overlay are collapsed, so neither contributes content measurement; `layout-preview-status` reports `Layout preview: empty`. Toggling again restores the same populated child content.

The Layout page also contains a static inspectable layout and text lab. It demonstrates native `row` and `column` direction, `gap` beside padded blocks, weighted grow/shrink, a fixed-width item beside a flexible remainder, min/max sizing, horizontal/vertical alignment, character wrapping, and nowrap ellipsis. Its stable probes are `layout-direction-row`, `layout-direction-column`, `layout-grow-primary`, `layout-grow-secondary`, `layout-width-fixed`, `layout-width-flexible`, `layout-shrink-left`, `layout-shrink-right`, `layout-bounds-probe`, `layout-alignment-horizontal`, `layout-alignment-vertical`, `layout-wrap-label`, and `layout-ellipsis-label`. The authored CSS subset has no `margin`, `flex-direction`, `flex-basis`, `justify-content`, `align-items`, or browser `overflow`; native tags provide direction, `width` supplies the fixed-size comparison, horizontal/vertical alignment uses the supported slot properties, and text overflow is limited to `clip` or nowrap `ellipsis`.

The document requires the host to register the generic shared adapters for search, text input, checkbox, number input, slider, select, tabs, menus, table, tree, repeat, and dialog. The Forms `gallery-slider` uses its registered custom CSS properties: teal normal/hover/disabled bar colors (`#2b7a78`, `#53d9d0`, `#52616d`), gold normal/hover/disabled thumb colors (`#f6c85f`, `#ffe19a`, `#77828d`), an 18px square thumb, and a 6px bar. The `composition` page uses the registered dialog's `content` and `body` slots. It deliberately does not claim support for unregistered custom debugger widgets or browser-only controls.

Both `gallery-records` and `gallery-tree-lab` use the shared `gallery-context-actions` menu. Its `gallery-context-inspect` context action records the native target key in `gallery-context-action-key` and increments `gallery-context-action-count`; it does not derive the inspected key from table or tree selection.

The Compose page also includes `gallery-slot-probe`, a gallery-only retained custom factory with required `content` and optional `details` slots. The authored child layouts remain in this document; the factory only mounts persistent slot boxes. `Omit details` reloads the installed resource in memory without the details slot, `Reinsert details` reloads the installed baseline, and `Reject reload` changes only the probe `mode` literal so its `PrepareReload` rejects before publication. The visible status/state/count bindings report the live qualified details scroll at `gallery-dialog/content/gallery-slot-probe/details/slot-probe-details`; a held removed details action is inert and reinsertion supplies a fresh action.

The Compose page includes `capability-nested-tabs`, an ordinary native nested tabs lab outside any repeat scope. Its three stable keys are `overview`, `details`, and `history`. `Details enabled`, `Long Details label`, and `Reset lab` are native actions outside the tabs container. When disabling an active Details panel, the model first selects Overview; the native tabs control then reconciles the bound selection, panel visibility, and focus. The Details panel contains `capability-nested-details-draft`, whose typed change and required commit callbacks keep its draft in the gallery model across tab selection changes.

The Repeats page includes `gallery-tree-lab`, a bounded native tree outside the Data splitter. Its model starts with `tree-root` and children `tree-alpha` and `tree-beta`; the action controls insert `tree-gamma`, reverse children, remove the selected node, reinsert the remembered removal, or reset the lab. `gallery-tree-status`, `gallery-tree-count`, and `gallery-tree-selection` keep mutation state readable beside the native selection callback.

The Menus page includes an inspectable reload lab. Its compatible control reads the installed CkTests gallery markup and stylesheet through the plugin manager, changes only the `commands-description` literal in memory to `Compatible reload applied.`, then submits it to the current view. It does not write a resource file or promise retention of ordinary button and editor state. The rejected controls validate the exact authored marker for their intended mutation, then submit only an in-memory malformed-markup, missing-text-binding, missing-required-action, or unsupported-style candidate. A missing read or marker is reported as `Setup failure` without calling `TryReload`; rejected candidates keep the accepted source active. `reload-failure-kind`, `reload-diagnostic`, and `reload-revision` display the last result and the active view revision.

The Menus page also mounts the model-owned `gallery-batch-preview` native second view exactly once. Its two buttons exercise an atomic two-view reload: the accepted candidate changes only the literal `batch-main-state` text, while a malformed second candidate leaves both accepted views unchanged. The batch status, combined revisions, and action count make ownership and failure inspection explicit.
- Changed/commit callbacks: `select-gallery-page`, `gallery-query`, `gallery-select-changed`, `gallery-edit-text-changed`, `gallery-edit-text-committed`, `gallery-checkbox-changed`, `gallery-number-changed`, `gallery-number-committed`, `gallery-slider-interaction`, `gallery-select-record`, `gallery-select-navigation`, `gallery-tree-selected`, `gallery-nested-tabs-selection-changed`, `gallery-nested-tabs-draft-changed`, `gallery-nested-tabs-draft-committed`, and item action `gallery-repeat-toggle`.

The host exposes `ck.CapabilityGallery.Open` and `Request_OpenCapabilityGallery()`. It supplies a nonnegative Slate owner for the dialog. Unsupported capability text is data-driven through `gallery-unsupported-summary`; the gallery must not replace it with browser emulation.
